# 코드 검토 결과

재현한 P2 문제5개를 수정했다. 검토 전 최초 실패와 수정 후 결과는 별도로 보존했다. 새로운 실차 주행 결함을 확정한 결과는 아니다.

| 재현 문제 | 영향과 수정 | 직접 재검사 |
|---|---|---|
| 레이더 입력 오류 뒤 재구성 시 오류 이력 소실 | 이전 정상 레코드를 잃었는데 정상 빈 결과로 보일 수 있었다. 명시한 native 복구 API에서 오류를 유지하고 객체/필터를 비우며 번호를 이전 객체와 분리한다. 정상 CRC 레코드로만 복구한다. | receiver/helper69통과·실제 IPC2생략. stock CAN만 들어오는 동안 오류 유지, 정상 레코드 뒤 복구/ID 증가 확인 |
| ignored인 새 목적지를 적용 전 놓침 | Git 변경 목록에서 새 helper가 빠져 적용 후 실패하면서 소스가 이미 변경됐다. 새 목적지의 ignore 여부를 사전 검사한다. | 원형 반례 재검사에서 적용 전 거절·생성/소스 변경 없음 |
| 보고서 부모 경로 전환 | 동시 경로 전환 뒤 저장소 안에 보고서를 쓸 수 있었다. 기존 부모만 허용하고 플랫폼 디렉터리 핸들과 배타적 쓰기에 묶는다. | Linux 경로 전환 반례 적용 전 거절·repo 안 보고서 없음. Windows 도구40시험 별도 통과 |
| manifest의 임의 artifact 읽기 | 허용하지 않은 assets 안 더미 파일을 읽은 뒤 hash 오류로 거절했다. 정확한3patch 목록/군별 경로를 읽기 전에 제한한다. | 더미 파일 읽기0회. 실제 시크릿 유출을 재현했다는 뜻은 아님 |
| 기존 신호 시험의 부분 객체 호환성 | 생산 생성자에는 속성이 있지만 기존 원형 시험 객체에는 없어3건 실패했다. 최종 clip의 속성 부재 시 원형 기본 동작을 유지한다. | 원형 신호 출력3통과·시험 fixture 변경 제거 |

레이더 복구 변경은 정확한 native 수신기의 정수 API1에만 적용한다. 일반 Toyota와 Bosch는 원형 생성 경로를 유지한다. 수신 시간과 마지막 CAN 시각의 관계는 공통 clock 계약에 의존하므로 근거 없이 새 시간 문턱을 넣지 않았다. 센서 취득/발행/수신 시각 구분은 여전히 추가 자료가 필요하다.

별도 실제 solver240틱 대조에서 RAV4 직접 제어의 유한 출력/명령 범위, Corolla 직접 제어와 RAV4 순정 경로의 원형 배열 일치를 확인했다. 이 입력에서 편안함 완화는0이었고 합성20Hz 계산이었다. 물리 운전·전체 호스트·인식·실시간 마감 검증으로 확대하지 않는다. ECU/PCS/AEB/회생/ARM 전체 빌드도 미완료다.

도구는 모든 파일 시스템 변경을 하나의 전역 transaction으로 만들거나 자동 원복을 보장하지 않는다. 적용 뒤 보고서 저장이 실패하면 소스가 이미 적용됐다는 실패를 구분한다. 원형18파일 태그/ZIP와 이전 근거는 덮어쓰지 않았다.
