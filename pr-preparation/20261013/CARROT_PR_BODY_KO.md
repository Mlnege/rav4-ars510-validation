RAV4 TSS2 2022의 실제 ARS510 객체 CAN을 fused 디코더에서 당근의 RadarInterfaceBase/MyTrack으로 연결합니다. 기존 외부 ARS wrapper는 점을 반환하지만 당근의 self.pts/트랙 이력과 ground 속도를 채우지 않아 객체 가속도·jerk 갱신이 누락됐습니다. 모델 선택에 따른 수신 능력 선언과 실제 정상 레코드 생성 조건을 분리합니다.

지원 범위는 정확한 `TOYOTA_RAV4_TSS2_2022`와 기존 `ToyotaFlags.RADAR_ACC`입니다. 최신 `ars510-radar` fb5b29c2의 Python 9파일과 MIT LICENSE를 원문 그대로 포함합니다. CRC·연속 프레임·시간·DLC·ID를 검사하며, 실제 DLC4인 요약 CAN을 잘못 거절하던 첫 후보와 Toyota SPEED 체크섬 오류를 그대로 사용하던 경로를 수정했습니다. 완료 레코드마다 실제 MyTrack에 ground 속도를 전달하고 누락 객체·손실·오류는 빈 상태 또는 임시 불가로 처리합니다. 명목 주기는 관측된 60ms입니다. 필터 계수·신호 정의·근거리 정책은 변경하지 않습니다.

같은 RAV4의 직접 종방향 경로에서는 기존 인터페이스의 명령 범위(-3.5,+2.0m/s²)를 MPC와 최종 목표에 반영하고, 호스트 감속 요청의 목표0을 당근 목표로 덮지 않도록 보완합니다. 명시한 stopping/비양수 요청에 이전 양수 PID·명령이 남는 경우도 다음 정규 CAN 출력에서 막습니다. PCM 모드0은 유효한 순정 설정속도 변경·재개를 관측해 기본 목표와 동기화하고 로컬 버튼 입력 및 지도·커브의 낮은 목표를 유지합니다. 새 버튼 CAN 스패밍은 없습니다.

다른 차종의 factory/기본 MPC·제어기 경로를 유지합니다. 현대/Bosch, 공통 MyTrack/DPath, 최신 신호·야간 처리, Panda 안전 규칙과 기존 ECU 초기화 결정은 변경하지 않습니다. KR/EN 사용자 안내와 별도 기술 보고서를 포함하며 PCM 설정 Wiki의 MANUAL 변경안도 별도 패치로 제공합니다. 외부 ARS 설치기와의 native dispatch/패키지 소유권 호환은 별도 ARS 후보 브랜치로 검토합니다.

직접 검증:

- 원본 세 로그의 실제 CS 배치 재생: 정상 레코드 2,399개, MyTrack 전달점 367개. 원형 fused와 레코드·객체별 거리/속도 값의 Float32 차이0, 현재 동역학 불일치0, B4 체크섬 오류0. 결과의 구조·전달 조건71개 실패0.
- 최종 receiver 53개 통과. PCM63 + 실제 C/Cython MPC·planner/정지 제어66의 격리 혼합129개 통과. 일반 시험 수집에서는 명시 opt-in 없이는 공통 IO를 교체하지 않음도 확인했습니다.
- 기존 타차 레이더708개 통과. 컴파일된 Linux msgq/Params가 필요한 프로세스2개는 미검증입니다. 최초 미빌드/DBC 준비 실패와 수정 후 실행을 구분해 기록했습니다.
- Toyota37개 모델 × 직접 제어 요청2조건의 CP 생성 비교74개에서 허용한 RAV4 지원3필드 외 차이0, 종방향·안전 설정 동일.
- 새 수신/시험/IO helper의 Ruff·구문 검사, 사용자 문서 매핑과 Wiki2페이지 검증 통과. 기존 신호 fixture는 기본 필드1개만 추가하고 기존3조건을 확인했습니다. 해당 파일의 기존 Ruff 지적22개는 원형과 동일합니다.

원본 제어는 모두 OFF입니다. 기록은 이미 개발에 사용한 자료이며 별도 보류 로그 성능 평가가 아닙니다. native 계산에는 현재 MPC Python 본문과 동일한 독립 사본 및 ABI가 맞는 기존 실제 solver를 사용했으며 전체 Konik/ARM 빌드를 새로 통과한 것으로 주장하지 않습니다. 전체 호스트 권한·실차 제동/회피·PCS/AEB·회생·실물 ECU/FW·실시간 마감은 미검증입니다. 기존 alpha-longitudinal의 ECU 초기화 경계도 별도 검증이 필요합니다.
