# 선택 파일 패치 검증 결과

공식 최신 `carrot-wip`을 유지하면서 필요한 부분만 덧붙이는 방식을 준비했다. 기존 당근 실행 파일은6개만 바꾸고 최신 ARS 디코더와 연결에 필요한12개를 추가한다. 레이더13·PCM2·종방향3개로 나눠 선택할 수 있다. 문서·테스트·검사 helper15개는 실행용 패치에 넣지 않았다.

기존 변경6개는 Toyota `interface.py`, `radar_interface.py`, `carcontroller.py`와 `cruise.py`, `longitudinal_planner.py`, `long_mpc.py`다. 수정 파일 목록과 지문은 `실행파일_18개.csv`에 있다. 값 개선은 검증된60ms 주기와 ground 속도/객체 동역학, 기존 명령 범위·감속 요청/정지 명령·PCM 관측 연동에 한정했다. 필터 계수·회생제동 값을 임의로 조정하지 않았다.

626 기준은 원래193 후보의 검증 기준이다. 이후0611의 UI·health 개선이 추가됐으며 실제 공식0611 clone에서도 현재 선택 자산이 검사·적용됐다. 미래 업데이트가 핵심 파일을 바꾸면 가드가 자동 거절하고 새 최신 clone은 덮어쓰지 않는다. 최신 버전을 계속 쓴다는 것은 미검증 패치를 강제로 재적용한다는 뜻이 아니다.

`PR_전체_검토용.patch`는 문서·회귀시험을 포함한33파일 PR 검토용이다. 사용자 실행 준비는 `assets/patches/`의 세 선택 패치를 사용한다. [최신 Carrot PR 비교](https://github.com/ajouatom/openpilot/compare/carrot-wip...Mlnege:codex/rav4-ars510-carrot-latest?expand=1)와 [ARS PR 비교](https://github.com/ds-sebastian/ars510-radar/compare/main...Mlnege:codex/carrot-native-ars510-dispatch?expand=1)에 후보를 올렸고 실제 PR 제출은 하지 않았다.

실제 ECU/펌웨어, PCS/AEB 보존, 회생 배분, Konik/ARM 전체 빌드, 전체 호스트 권한·실시간 마감·물리 제동은 미검증이다. 이미 실제 상태는 모든 기록에서 제어OFF였다. 기존 alpha-longitudinal의 ECU 초기화 경계도 수신 패치만으로 해결됐다고 판단할 수 없다. 차량 설치·제어 활성화·CAN 송신·Panda 우회·운영 설정·시크릿 변경은 실행하지 않았다.

최신 clone에 필요한 파일만 적용하는 준비 명령은 README에 있다. 공식 Python 요구 범위와 별도 빌드 의존성이 필요하며 스크립트는 모델/LFS·장치 빌드·운영 교체를 자동으로 하지 않는다. 자료는 익명 개수와 검토 소스만 포함한다.
