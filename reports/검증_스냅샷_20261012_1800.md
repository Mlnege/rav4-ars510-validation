# RAV4 2022 종방향·레이더·회생제동 검증 스냅샷

2026-10-12. 실제 CAN의 수신·객체 디코딩과 기존 당근레이더 코어 연결을 확인했고, 오프라인에서 재현된 일부 제어 결함을 수정했다. **실차 호환성·회생제동·PCS/AEB의 안전성을 완벽히 입증한 결과는 아니다.** ACC 보조 관측이 누락되거나 오래된 모의 입력, 정지거리가 부족한 조건에서 충돌이 남아 있다. 차량에 실험 메시지를 보내거나 제어를 활성화하지 않았다.

## 실제 자료와 모의 조건

제공된 저장 로그 4개를 기록 당시 전체 cereal 스키마로 읽었다. CarrotPilot 기준은 `carrot-wip`의 `0e4ee1bdbef3ad7284b136fddf31592e3f8a785f`, ARS510 자료는 `673eb8e609e303feff2c15dd250592c383962156`으로 고정했다. 해당 CarrotPilot 원격 브랜치도 작업 중 다시 확인했다.

실제 로그의 `carControl.enabled/longActive`는 모두 False이다. 추가 요청에 맞춘 PC 모의주행은 `longActive=True`와 제어 권한 허용을 전제로 실제 CarrotPlanner→native MPC→LongControl→Toyota CarController→실제 DBC 0x343 계산을 사용했다. 가상의 선행차·비전·ARS 패킷과 차량 지연·1차 응답을 입력했고, 실제 카메라 인식이나 Toyota 물리 모델로 대체 주장하지 않는다. 신호 전용 검사는 실제 runtime→CarrotPlanner→MPC→직렬화→LongControl까지이며 Toyota ECU나 신호 인식 자체를 포함하지 않는다.

## Vision Only·전방·코너·당근레이더

RAV4 2022는 RADAR_ACC 플랫폼으로 현재 Toyota DBC에 radar 항목이 없어 `radarUnavailable=True`가 된다. 실제 코드의 유효 레이더 모드는 Toyota에서 그 값에 따라 −2 또는 1이며, 설정 Mode2를 그대로 적용하는 Hyundai 경로와 다르다. 문서의 `CarrotRadarMode` 선택 설명과 현재 manager의 `radard_dpath` 등록도 다르다. 따라서 UI 문구만 바꾸거나 설정만 반복해 객체 파이프라인이 생기지 않는다.

실제 ARS 객체 CRC 2,433개·메타 CRC 2,436개가 통과했고 독립 DBC 대조의 객체 슬롯 2,878개에서 불일치 0이었다. fused 발행 369표본을 실제 Carrot 후처리·직렬화·당근 lead 선택 코어로 전달했고, 모델 업데이트 2,792회 중 레이더 L1 선택 175회였다. 이는 수신·선택의 증거이며 차량 감속 성공률은 아니다. 불완전한 레코드는 거절했다.

0x235/0x237은 ARS 전방 ACC 보조 자료의 8바이트 신호이며 Hyundai 코너의 32바이트 메시지와 다르다. Toyota BSM 0x3F6은 경고 boolean만 있고 거리·속도·객체 ID가 없다. 실제 Toyota 코너 객체 프로토콜과 끼어들기 실차 성공 사례는 미확인이다. 전방과 당근 코어는 재사용할 수 있으나 코너 트랙이나 알 수 없는 trackState를 생성하지 않았다.

이전 공유 대화의 부품번호 후보·지원 펌웨어 문자열은 카탈로그/저장소 사례였다. 실제 ECU 조회 응답이나 실물 라벨이 없고 carFw=0이므로 Continental ARS510 제조사·모델·펌웨어를 최종 확정하지 않았다.

root90분은 실제10ms간격 제어·20Hz계획·약33HzCAN 생성에 맞춰 실행한다. 신호61분은 실제50ms계획 주기 안에 가상10ms간격 제어5회를 연속 호출하므로 전체제어의 실제100Hz벽시계 검증으로 부르지 않는다. 마지막 CAN 수정 후에는 실제10ms분산호출의 별도35분 연결 검사를 진행한다. 접촉 뒤 적분은 유효한 물리 주행으로 해석하지 않고 첫 접촉까지를 판정한다. 일반 runtime watchdog 전체, Konik 실행 시간, 실제 카메라·센서 지연과 ECU 응답은 별도 검증 대상이다.

정지 신호 사례는 실제 longActive=False 동안 출발금지 상태가 초기화돼, 활성화 이후0.15초 동안 빨강 확인이 필요하다. 이번 출력 수정은 **확인된 hold 뒤 다음 정규 CAN부터**를 보강하며, 확인 전 이동·발행된 이전 명령·가정한 차량 응답 지연을 없앤다고 주장하지 않는다. 초록0.7초 확인 후에도 원래 모델의 정지 판단은 유지한다.

## 회생제동: 롱컨 활성 전제

순정 하이브리드 회생 기능과 CarrotPilot의 ACC 감속 요청에서 회생/마찰을 얼마나 분담하는지는 별도다. 현재 Toyota 출력에는 회생을 직접 선택하는 새 명령이 없고 일반 `ACCEL_CMD/ACC_TYPE/PERMIT_BRAKING`을 사용한다. 제동 허용을 꺼서 회생을 강요하지 않았다.

실제 CP는 이벤트가 있는3로그의5CP에서 FW0·HYBRID 비트 없음·응답 모델 지연 약0.15초였다. 네 로그의 수동 차량 선택과 조회생략 코드가 일치하며 FW0을 조회실패로확정하지 않는다. HYBRID 표시는 펌웨어 조회에 따라0.05초 CP 모델을 선택하는 조건이며 회생 ON/OFF 스위치가 아니다. 최신 계획기는 별도 LongActuatorDelay 설정을 읽고 gear/GVC/brake 파서는 HYBRID 비트로 선택되지 않는다. 부재를 회생 실패나 잘못된파서 원인으로확정하지 않았다.

기존 0x127 FDRVREAL 9,646표본과 0xA6 BRAKE_FORCE 13,189표본을 독립 비트 추출과 대조해 불일치0, 0x127 체크섬 오류0을 확인했다. FDRVREAL의 음수1,045표본은 엔진 제동과 회생이 섞일 수 있고, BRAKE의 raw255 총775표본은 포화/무효 의미가 미확인이다. 따라서 실제 회생량이나 마찰 제동력 보정값을 확정하지 않는다.

롱컨 활성·평지·고정질량 가정의 계산은 소스 공통 RAV4 CP 질량1762.127kg을 사용했다(한국형 HEV 실측질량 아님). 평동 운동에너지 감소는 `m(v초기²−v최종²)/2/3600 Wh`이다.

| 속도 변화 | 해당 가정의 운동에너지 감소 |
|---|---:|
| 30→0km/h | 16.996Wh |
| 50→0km/h | 47.211Wh |
| 80→0km/h | 120.859Wh |
| 100→0km/h | 188.843Wh |
| 100→50km/h | 141.632Wh |

100% 회수하면 이 운동에너지 성분을 모두 회수한다는 조건부 예산이다. 회전체·구배·엔진 발전·저항·모터 한계·배터리 수용전력·변환 손실을 포함한 실제 충전량이 아니다. 모의 trace의 감속 중 에너지 감소·순간 전력도 별도 JSON에 있으며 배터리 회수량은 null로 남겼다.

[OneClone 제품 설명](https://oneclone.net/product/toyota-radar-acc-filter/)은 0x343 제어 경로와 일부2022 RAV4 지원을 설명하지만 회생 복구·한국형 펌웨어 호환·PCS/AEB 보존 명세를 제공하지 않는다. 특정 필터 구성과 UDS 차이를 설명한 [ARS 버스 분석](https://github.com/ds-sebastian/ars510-radar/blob/673eb8e609e303feff2c15dd250592c383962156/docs/13_car_bus_messages.md), [PCS/AEB 조사](https://github.com/ds-sebastian/ars510-radar/blob/673eb8e609e303feff2c15dd250592c383962156/docs/15_aeb_pcs.md)도 이번 차량이나 해당 제품의 회생 복구 증거가 아니다. 기본 HEV 회생 설명은 [Toyota 공식 자료](https://www.toyota.ca/en/connect/2022/hybrid-electric-batteries/)를 확인했다. 필터 구매·배선·UDS 제거·새 필터 플래그·실차 CAN 송신은 실행하지 않았다.

## 미완료·추가 자료

1. 실제 레이더·Hybrid/브레이크 ECU 식별/펌웨어와 비식별 실물 라벨, 한국형 프로토콜·물리 신호 보정 근거.
2. 실제 롱컨 활성 상태의 연속 rlog, 객체80/85 전체 레코드·235/237 현재/누락·가감속 요청·aEgo·운전자 조작·제어권한·PCS 출력의 동시 기록. 가용한 정밀 배터리 전압/전류/SOC/온도·모터 발전 자료는 공식 정의와 함께 필요하다.
3. OneClone 정확한 하드웨어/펌웨어·배선·차단/수정/전달 프레임·통신 실패 동작과 한국형 지원·PCS/AEB 유지 자료.
4. 실제 카메라 원본 영상·신호 정답 라벨·Konik 처리 시간. 현재 메타데이터와 합성 색 입력으로 인식 정확도나 전체 신호 정지를 입증하지 않는다.
5. Toyota 코너 객체 CAN/DBC와 안전 기능 별도 검증. BSM boolean을 코너 객체로 쓰지 않는다.

## 배포·적용

GitHub는 사용자 계정의 전용 검증 저장소로 분리한다. 운영 CarrotPilot·NAS·차량 설치에는 자동 적용하지 않는다. 고정 소스 clone→8개패치 검사→파일 해시→Python/CPU/기존 소스 조건 확인→별도 가상환경 준비 명령을 제공하며, 배포 manifest의 `vehicle_deployment_allowed=False`를 유지한다. 자세한 명령·필요 파일은 배포 README, 개별 분석표·수정 파일 목록은 결과 묶음에 있다.

## 이어서 조사할 근본 원인

단일 결함 수정과 전체 원인 해결을 구분한다. 현재 재현된 사슬은 정상 raw 해석→불확실성이 큰 fused 속도 추정(ACC 추가 관측 누락)→MyTrack 초기 상태→레이더 L1 선택→낙관적인 미래 거리로 이어진다. 정지 출력 보강은 이 센서/추정 문제를 해결하지 않았다.

실제 시간도 별도 계약이다. 합성 시계의 입력 age와 실제 OS 지연을 동일하게 놓을 수 없다. 최신 실제10ms목표 연결 검사는 최대322.91ms 뒤처짐을 관찰했고, 현재 도구의 합성 신선도는 이 시간을 자동 반영하지 않는다. 실제 앱의 model/plan 헤더와 카메라 capture time, 수신 생존 판단, soft-disable 및 card 최종 송신 조건을 원형 코드/고장 주입으로 계속 확인한다. 지금 수치만으로 실제 차량의200ms 신선도나 제어 마감시간을 보장하지 않는다.

차량 식별도 증상과 효과를 나눠 조사한다. HYBRID 비트 부재의 확인된 효과는0.05초 전용 응답 모델 미선택이다. 최신 gear/GVC/brake 파서는 그 비트로 선택되지 않으므로, 부재를 잘못된 기어·GVC 파서나 회생 OFF로 연결하지 않는다. 실제 펌웨어 조회와 수동 차량 선택/설정 경로는 비식별 허용 필드만 추가 분석한다.
