# 원본 CAN 묶음·차량 설정·안전 정책 통합 검증

정확한 원본 CS·CAN 묶음과 원본 CP, 기록된 Panda 모드 전환을 한 메모리 호스트 경로에 연결했다. 새 liveTracks 발행 헤더는 저장순서 최대 헤더를 사용한 가정이며 **실제 ARS 발행 P는 미관측**이다. 이 범위에서 실제 CAN의 점 발행 367개·CRC 정상 레코드 2,399개를 처리했고 레이더 선행 입력 175회가 native MPC까지 전달됐다. 원본 OFF·운전자 상태·오류·시각을 정상값으로 바꾸지 않았다.

| 검사 | 직접 실행 결과 | 의미와 제한 |
|---|---|---|
| 원본 3개 로그 통합 | 연결 54검사 실패0 | 자료 부족 1개는 채우지 않았고 별도 제외 |
| 원본 CP 생성자 대조 | 검사한 필드 차이0 | a/d는 직접73, b는 순정585를 유지. 전체 필드·ECU 정체 검증이 아님 |
| 주요 NS/header wire 대조 | 30,215표본 차이0 | epoch 보존 확인이며 BOOTTIME/MONOTONIC 실물 동기 보증이 아님 |
| 실제 C 반환 관측 | 24,326개 중 허용23,912·거부414 | 모두 메모리 CAN, 실제 송신·제어 권한 획득 없음 |
| 독립 TX 기대값 대조 | 정의3,191개 불일치0 | 미정21,135개는 정책 판정 통과로 세지 않음 |
| 부모의 대표 a/b 재실행 | 각18검사 통과·34결과군 차이0 | 별도 복사본 실행이며 원래54검사와 합쳐 전체 실행 수를 만들지 않음 |

호스트 활성화와 longActive, C 제어 권한·릴레이 오류·RX-invalid는 모두0이었다. stock CP인 log_b에서는 ACC 명령을 생성하지 않았고, 원본 직접 롱컨 CP인 a/d에서도 비영 ACC 요청은0이었다. LKA/LTA/HUD 등의 실제 C 허용 관측은 전체 steering 정책의 독립 검증이나 실물 순정 안전 기능 보존 증명이 아니다.

원본 CAN 838,315항목을 물리RX647,115·송신반환191,166·거부통지34로 보존했다. RX와 TX는 같은 단일 C 상태를 사용했고 모드가 실제 기록에서 바뀔 때만 정식 설정 함수를 호출했다. 반복 reset·제어 권한/릴레이 강제 setter·init_tests는 연결하지 않았다. 1Hz 위상0과 100Hz 호스트 격자도 재생 가정이며 실제 MCU·소켓·실시간 마감 검증은 아니다.

이 통합은 source12와 안전 C .so의 실행 전후 지문을 확인한 범위다. 최초 a의 source 관측 범위는5개였고 이후 버전·부모 재실행에서는12개로 넓어졌다. 완료 후 부모가 native MPC 관련 파일6개를 기존 동결 빌드와 대조해 같음을 확인했지만, 이번 실행 전에 MPC 지문을 새로 계측한 결과는 아니다. 동결 JSON의 all_shared_library_fingerprints_unchanged 검사는 안전 C .so에 한정해 읽는다. native 실행, 과거 빌드 근거, 현재 파일 지문을 하나의 신규 빌드 검증으로 합치지 않았다.

기존 운영 liveTracks 2,773개에는 점이 없었다. 새 ARS 발행 P의 출처로 그 헤더를 쓰지 않았으며 별도 시간 진단에서는 P 후보를 입력하지 않고 상대값만 계산했다. 실제 CAN·Card·카메라의 시계 영역, 소켓 수신·처리 시간과 새 ARS P를 측정하기 전까지 실물 시간 정렬과 제동 타이밍을 확정할 수 없다. Linux에서 BOOTTIME은 절전 시간을 포함하고 MONOTONIC은 포함하지 않는다는 차이도 이 범위와 구분했다. [Linux 공식 시간 문서](https://www.kernel.org/doc/html/latest/core-api/timekeeping.html)

r9는 분석·진단 자료 갱신이다. 소스63개·패치8개·manifest는r8.1과 바이트가 같다. ECU 제조사·모델·펌웨어, 활성 운행의 급제동·신호 제동·재출발, 회생·PCS/AEB·ARM 전체 빌드·설치 Panda·MCU 동작은 여전히 미완료다. 실차 배포 허용은False이고 차량 송신은0이다.
