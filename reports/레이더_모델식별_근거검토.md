# 레이더 프로토콜 호환과 실물 모델 식별의 경계

현재 확인된 것은 저장 CAN이 ARS510 프로젝트의 레코드 구조와 맞고 객체를 해석할 수 있다는 사실이다. **경준님 차량의 ECU 제조사·모델·펌웨어는 아직 확정되지 않았다.** 새 차량 조회·CAN 송신·설정 변경은 하지 않았다.

| 근거 | 확인할 수 있는 내용 | 확인할 수 없는 내용 |
|---|---|---|
| 기존 직접 검사: 객체 CRC2,433·메타 CRC2,436 정상 | 분할 구조와 체크섬 호환 | 물리 송신 ECU의 제조사·품번 |
| 기존369 객체 표본→당근 처리 | 현재 디코더·인터페이스의 오프라인 연결 | 실물 거리/속도 정답과 제동 안전 |
| 현재0x85 디코더 | prefix·10개 차선/도로 곡선 셀·CRC 구조 | 검증된 제조사/모델/FW 식별 필드 없음 |
| CarrotPilot 기준 fingerprint 표 | 2022 플랫폼에는 공개FW `8821F0R01100`, 2023 플랫폼에는 `8821F0R03100` 등록 | 수동으로 고른 차량명이 실제 FW 응답을 대신하지 않음 |
| ARS 프로젝트의 외부 차량 분석 | 두 FW가 같은 CAN 메시지 계열을 사용한다고 보고 | 경준님 차량에 어느 FW가 달렸는지 |
| 첨부 로그의 carFw0 | 실제 FW 응답 정보가 없음 | 조회 실패·레이더 미지원·특정 FW로 단정 불가 |

현재 설치기 `detect(ret, fingerprint, car_fw)`는 플랫폼명과 RADAR_ACC만 사용한다. 전달된 CAN fingerprint와 car_fw를 그 함수의 감지 조건에 사용하지 않는다. 따라서 설치기의 탐지 성공을 실물 식별 성공으로 취급할 수 없다. 검사 대상은 고정 커밋의 소스이며 설치기를 실행하지 않았다.

같은 관측 특성을 보이는 둘 이상의 알려진 FW가 존재하므로, CAN ID·주기·CRC만으로 FW를 하나로 고르는 설명은 성립하지 않는다. 이는 식별 근거 부족이라는 판단이며, 특정 FW나 ECU가 잘못되었다는 진단이 아니다. `0x85`의 미해석 바이트를 모델번호로 추측해 새 필드를 정의하지 않았다.

확정에 필요한 자료는 기존에 확보한 실물 라벨의 제조사/형식/품번, 또는 기존 읽기 전용 ECU 버전 결과다. VIN·시리얼·개인 위치·장치 식별정보는 제외하고, 공개 결과에는 알려진 지원목록과의 일치 여부만 남긴다. 이 작업에서 추가 실차 조회를 실시하지 않는다.

이 보고서는 기존 실행 근거를 읽어 식별 가능성을 재검토한 것이다. CRC·재생 테스트를 새로 실행하거나, 외부 저장소의 차량 시험을 직접 수행한 것으로 보고하지 않는다. 외부 자료의 제조사 명칭은 해당 연구자의 설명이며 실물 OEM 라벨을 독립 확인한 결과가 아니다.
